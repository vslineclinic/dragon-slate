# 부대 전투 · 큰 전장 · 굴림 석판 설계 (2026-11-23)

## 1. 왜 바꾸나
사용자가 직접 해 보고 이렇게 말했어요.
- 전투 화면이 작아요. 게임 창도 모니터의 절반 정도밖에 안 돼요.
- 카드로 뽑은 드래곤끼리만 싸우니 단조로워요. 웨이브마다 졸병 무리와 우두머리 드래곤이 함께 나오는 부대 전투가 낫겠어요.
- 아래 패널 말고 전장에 바로 드래곤을 놓고 싶어요.
- 석판이 주사위처럼 굴러가는 느낌의 애니메이션이었으면 해요.
- 전장 배경 그림이 필요해요.

참고: 슬롯바운드(오토배틀러 + 타워 디펜스). 큰 전장에 병사를 앞뒤로 세우고, 아래쪽 슬롯으로 유닛을 뽑아요. **장르 구조와 배치 방식만 참고해요.** 그림·화면 모양·용어는 우리 것을 써요. "코어" 같은 말은 이미 금지어예요.

### 사용자 결정 (2026-11-23)
- **Godot판만 개발해요.** 웹판(packages/*, apps/web, tools/sim, tools/parity)은 지금 상태에서 멈추고 고치지 않아요.
- **양쪽 다 부대로 싸워요.** 적은 졸병 무리와 우두머리 드래곤으로 나와요. 내 드래곤도 등급에 따라 새끼 용 호위를 데리고 싸워요.
- 화면 배치는 제안한 그림대로 해요. 위쪽 약 70%가 전장이고, 아래 띠에 대기칸·석판·알 카드가 들어가요.

## 2. 목표 · 하지 않을 것 · 실패로 볼 것
**목표**
- 화면 대부분을 전장이 차지하고, 전투가 "부대끼리 맞붙는 장면"으로 보여요.
- 드래곤을 전장의 칸에 직접 끌어다 놓아요. 앞줄(전열)과 뒷줄(후열)이 실제로 다르게 작동해요.
- 석판을 돌리면 열마다 굴러가다 왼쪽부터 차례로 멈춰요. 탭하면 건너뛸 수 있어요.
- PC 창은 크게 열리고 크기를 바꿀 수 있어요. 휴대폰은 가로로 긴 화면 전체를 써요.
- 결정적(같은 시드면 같은 결과) 정수 계산과 Rng만 쓰는 core 규칙은 그대로 지켜요.

**하지 않을 것**
- 웹판을 따라 고치는 일
- 새로운 경제·상점·유물 시스템
- 소리 (지금 단계에서는 효과음 연결 없음)
- 실시간 조작 (전투는 여전히 자동이에요)

**실패로 볼 것**
- 화면이 졸병으로 꽉 차서 무엇이 내 드래곤인지 알아볼 수 없음
- 휴대폰에서 칸·카드가 손가락으로 누르기 어려울 만큼 작아짐
- 튜토리얼대로 한 첫 판의 1웨이브에서 자주 짐 (목표: 기본 드래곤 1마리로 1웨이브 승률 90% 이상)
- 같은 시드로 결과가 달라짐

## 3. 접근 방식 (검토한 안)
| 안 | 내용 | 장단점 |
|---|---|---|
| **A. 공간 전투 (채택)** | 유닛마다 x 위치(정수)와 줄(lane 0~2)이 있어요. 졸병·호위는 걸어가 근접 공격하고, 드래곤은 제자리에서 멀리 숨결을 쏴요. | 장면이 살아나고 앞줄·뒷줄이 의미를 가져요. 전투 규칙을 새로 써야 해요. |
| B. 목록 전투 + 연출만 | 지금 규칙(첫 번째 살아 있는 적 공격)에 유닛 수만 늘리고 화면에서 걷는 척만 해요. | 빨라요. 하지만 위치가 결과와 상관없어서 배치하는 재미가 없어요. |
| C. 칸 단위 체스형 | 격자 위를 칸 단위로 움직여요. | 읽기는 쉽지만 졸병 무리가 몰려오는 느낌이 약하고 길찾기가 필요해요. |

A를 골랐어요. 사용자가 원한 "부대가 맞붙는 장면"과 "전장에 직접 배치"를 결과에 반영할 수 있는 유일한 안이에요.

## 4. 전투 규칙 (core, `godot/core/battle.gd` 교체)
### 4.1 전장
- 가로 좌표 x는 0~1000 사이 정수, 줄(lane)은 0·1·2 셋이에요. 화면 높이에 맞춰 세 줄을 그려요.
- 아군은 왼쪽, 적은 오른쪽에 서요.
- 둥지 6칸을 전장 위의 칸으로 옮겨요. 칸 번호는 지금과 같아요.
  - 전열 0~2: x = 260, 줄 = 번호 % 3
  - 후열 3~5: x = 140, 줄 = 번호 % 3
- 둥지 칸 잠금(nestOpen)과 해금 웨이브도 지금과 같아요.

### 4.2 유닛 종류
| 종류 | 누구 | 이동 | 사거리 | 비고 |
|---|---|---|---|---|
| dragon | 내 드래곤, 적 우두머리 드래곤 | 움직이지 않음(날아서 떠 있음) | 700 (사실상 전장 전체) | 숨결, 원소 상성 적용 |
| escort | 내 드래곤의 새끼 용 호위 | 앞으로 걸어감 | 40 (근접) | 주인과 같은 원소 |
| minion | 적 졸병 | 앞으로 걸어감 | 40 (근접) | 원소별 6종 |

- 표적은 **가장 가까운 살아 있는 적**이에요. 거리는 |x 차이| + 줄 차이 × 줄간 거리 120이에요. 거리가 같으면 줄 번호가 작은 쪽, 그다음 유닛 번호가 작은 쪽을 골라요.
- 걷는 유닛은 표적이 사거리 밖이면 매 틱 speed만큼 그쪽 x로 다가가요. 줄은 바꾸지 않고, x로만 움직여요.
- 드래곤은 움직이지 않아요. 그래서 걷는 유닛들이 가운데서 먼저 맞부딪치고, 그 뒤에서 드래곤들이 숨결을 쏘는 그림이 돼요.
- 공격 쿨다운, 원소 배율(135/75), 흡혈은 지금 규칙과 같아요.

### 4.3 내 쪽 호위 (escort)
- 드래곤 1마리마다 호위가 붙어요. 등급별 수는 `data/battle.json`의 `escort.count`에서 읽어요.
  - 초안: base 2 · t2 3 · t1 4 · dual 4 · secret 4
- 호위 능력치는 주인 드래곤의 최종 능력치(계승 특성·흡수 보너스를 반영한 값)에 비율을 곱해요.
  - 초안: hp 22% · atk 18% · 쿨다운 12틱 · speed 6
- 시작 위치: 주인 x + 50, 같은 줄. 여러 마리면 x를 12씩 앞으로 벌려요.
- 원소는 주인의 첫 원소예요. 흡혈은 없어요.

### 4.4 적 부대 (`godot/core/waves.gd`의 generate_enemies 교체)
- 우두머리 드래곤
  - 수: 1마리, 8웨이브부터 2마리, 14웨이브부터 3마리
  - 고르는 규칙은 지금과 같아요 (5웨이브까지 base, 그다음은 t2도 섞음).
  - 보스 웨이브에서는 보스 원소의 t1 드래곤이 첫 우두머리예요.
- 졸병
  - 수: min(4 + wave / 2, 14)
  - 원소는 그 웨이브 우두머리들의 원소에서 Rng로 골라요.
- 힘 예산: 지금의 enemy_power(wave)를 총예산으로 써요. 그중 `waves.json`의 `squad.leaderSharePct`(초안 55)를 우두머리에, 나머지를 졸병에 나눠요. 비율은 지금처럼 unit_power로 맞춰요.
- 위치
  - 우두머리 드래곤: x = 860 (2·3번째는 x = 900, 줄을 바꿔 가며)
  - 졸병: x = 700부터 줄을 돌아가며 놓고, 같은 줄이면 x를 30씩 뒤로 벌려요.
- 데이터 파일 `data/minions.json`(새로 만듦): 원소별 1종, 6종. 이름(한국어), hp, atk, cooldownTicks, speed를 담아요.

### 4.5 끝나는 조건과 보스 규칙
- 한쪽 유닛(드래곤·호위·졸병 모두)이 전멸하면 끝나요. maxTicks까지 안 끝나면 지금처럼 적의 승리예요.
- 보스 규칙은 아군 쪽에 이렇게 적용해요.
  - burn: 체력이 가장 낮은 아군 **드래곤**
  - rowBlast: 전열/후열을 번갈아 가며 그 줄의 드래곤과 그 드래곤들의 호위
  - pulse: 아군 전체
  - allySlow, enrage, healCut: 지금과 같아요.

### 4.6 화면용 기록 (events)
- 틱 0에 `spawn`을 남겨요: {id, side, kind, speciesId 또는 minionId, lane, x, hp}. id는 0부터 시작하는 전역 번호예요.
- 공격은 `attack` {tick, src, dst, dmg, mult, heal}, 죽음은 `death` {tick, id}, 보스 규칙은 `hazard` {tick, name, id, dmg}로 남겨요.
- 움직임은 4틱마다 `pos` {tick, xs: {id: x}}를 남겨요. 움직인 유닛만 넣어요.
- `run.gd`가 쓰는 결과 모양(winner, ticks)은 그대로예요. 둥지 칸 번호 ↔ 유닛 id 대응은 spawn에 `slot`을 넣어서 알려요.

## 5. 화면 (Godot UI)
### 5.1 창 크기와 비율
- 기준 해상도는 높이 720이에요. 가로는 1280(16:9)부터 1600(20:9)까지 늘어날 수 있어요.
- `project.godot` 설정: stretch mode = canvas_items, aspect = **expand**.
- PC 첫 실행: 모니터 작업 영역의 85% 크기로 창을 열고 가운데에 둬요(16:9 유지). 창 크기는 바꿀 수 있고, F11로 전체 화면을 켜고 끌 수 있어요. 마지막 창 크기는 저장하지 않아요(나중 일).
- UI는 화면 폭에 맞춰 다시 배치해요.
  - 전장은 폭 전체를 써요.
  - 아래 띠: 대기칸은 왼쪽, 석판은 가운데, 알 카드와 돌리기 버튼은 오른쪽에 붙여요.

### 5.2 배치 (1280×720 기준)
```
y 0   ┌ HUD 44: 웨이브 · 생명 · 마력 · 보스 예보 · 도감 · 배속 ───────────┐
y 44  │ 전장 (배경 그림) 446px                                            │
      │  후열칸 ▢  전열칸 ▢   ·  ·  ·  졸병들 ← ← ←   우두머리 드래곤      │  ← 줄 3개
      │  [놓아주기 칸]                                     [전투 시작]     │
y 490 ├ 아래 띠 230 ───────────────────────────────────────────────────────┤
      │ 대기칸 2×2 │ 석판 3×3 + ▲▼ │ 안내 2줄 / 알 카드 3장(가로) / 돌리기 │
y 720 └───────────────────────────────────────────────────────────────────┘
```
- 둥지 칸은 전장 위에 반투명 발판으로 보여요. 정리 단계에서만 테두리가 빛나고, 잠긴 칸은 자물쇠 표시예요.
- 놓아주기 칸과 전투 시작 버튼은 전장 아래쪽 모서리에 둬요(왼쪽 아래 / 오른쪽 아래).
- 끌어다 놓기: 대기칸 → 발판, 발판 ↔ 발판, 발판 → 대기칸, 드래곤 → 놓아주기 칸 모두 지금처럼 동작해요(합체·흡수 미리보기 포함). 지금 nest_panel.gd의 로직을 전장 쪽으로 옮겨요.
- 휴대폰에서 손가락 크기: 발판과 대기칸 카드는 최소 96×80(기준 해상도)이에요.

### 5.3 전투 장면
- 전투 동안 아래 띠는 어둡게 하고 입력을 막아요(지금처럼 단계로 막음).
- 유닛 크기: 드래곤 96px(지금 그림), 호위는 주인 그림을 52px로 줄여서 써요(새 그림 필요 없음). 졸병은 새 그림 48px이에요.
- 표시
  - 체력바는 드래곤만 항상 보여요. 졸병·호위는 맞을 때만 잠깐 보여요.
  - 아군 드래곤은 원소 색 테두리로 구분해요.
  - 숨결은 원소 색 투사체가 날아가는 선으로, 근접 공격은 살짝 앞으로 찌르는 동작으로 보여요.
  - 죽으면 흐려지면서 사라져요.
- 재생: `pos` 사이를 보간해서 움직이게 해요. 배속(1x/2x/4x)과 건너뛰기는 지금과 같아요.
- 배경: 웨이브 구간마다 다른 그림이에요(1~5 초원 유적, 6~10 얼음 협곡, 11~15 화산, 16~20 심연). 1600×446 기준이고 좌우로 잘려도 괜찮게 그려요.

### 5.4 석판 굴림 애니메이션
- 돌리기를 누르면 세 열이 위아래로 빠르게 흘러가요. 무작위 그림 띠를 쓰고, 칸 밖은 잘라서 보이지 않게 해요.
- 0.6초 뒤 1열이 멈추고, 0.18초 간격으로 2열·3열이 멈춰요. 멈출 때 살짝 넘쳤다가 되돌아오고(튕김), 그림이 한 번 커졌다 작아져요("굴린 주사위가 서는" 느낌).
- 다 멈추면 맞은 줄이 차례로 빛나고, 그다음 지금처럼 알 카드가 나와요.
- 석판 아무 곳이나 탭하면 바로 결과로 넘어가요.
- 결과는 core가 이미 정한 값이에요. 애니메이션은 보여 주기만 해요.

## 6. 그림 (코덱스 image_gen)
- 전장 배경 4장 (5.3의 구간별). 위에서 내려다본 측면 전장이고, 가운데는 비워 유닛이 잘 보이게 해요.
- 졸병 6종: 원소별 하나씩, 왼쪽을 바라보고 배경이 투명한 그림이에요. 지금 드래곤 그림과 같은 화풍으로 그려요.
- 저장 위치: `assets/backgrounds/*.png`, `assets/minions/<id>.png`. 원본은 `art/`에 둬요.
- AI로 그렸다는 표기는 지금처럼 정직하게 해요.

## 7. 개발 방식
- **Godot만 기준이에요.** `npm run parity`와 run 결과 일치 검사는 은퇴해요. rng 일치 검사는 남겨도 돼요. CLAUDE.md·AGENTS.md 규칙도 그렇게 고쳐요.
- 밸런스 시뮬레이션을 Godot으로 옮겨요: `godot/tools/sim.gd`. 화면 없이 실행하고, 웹판 tools/sim/bot.ts의 판단 규칙을 그대로 옮겨요. `npm run sim`이 이걸 부르게 바꿔요.
- 밸런스 목표
  - 정식판 20웨이브 클리어 약 45%
  - 기본 드래곤 1마리로 1웨이브 승률 90% 이상
  - 데모(10웨이브) 재앙 0단계 클리어 약 70%
- 분담: 전투 규칙·적 부대·화면 배치·애니메이션은 클로드, 그림과 시뮬레이터 이식은 코덱스 작업 카드로 맡겨요(작업본 `C:\claude\dragon-game-codex`).
