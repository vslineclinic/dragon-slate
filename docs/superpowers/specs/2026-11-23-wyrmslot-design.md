## 1. 무엇을, 왜 만드나

**한 줄:** 룬 석판(3×3 슬롯)을 돌려 드래곤 알을 얻고, 두 마리를 합쳐 신화 속 드래곤을 찾아내며, 자동 전투로 20웨이브를 넘기는 로그라이트.

**왜:**
- 혼자, 부업으로 만들어 스팀에서 돈을 버는 첫 게임이에요.
- 화려한 그래픽보다 "한 판만 더"를 부르는 재미와 중독성이 먼저예요.
- 슬롯은 규칙을 설명하지 않아도 바로 돌릴 수 있어서 진입이 쉬워요. 조합으로 숨은 드래곤을 찾아내는 재미가 오래 붙잡아요.

**개발 방식 자체가 홍보 거리예요:** 최대한 AI로 기획, 코드, 그림, 등록, 출시까지 하는 게 목표예요. 그 과정을 유튜브와 스레드에 개발 일지로 올리면서 진행해요.

**경쟁작과 다른 점:** 같은 3×3 슬롯 오토배틀 장르의 *Slotbound*(1인 개발, 2026-11 출시, 9.99달러)가 이미 있어요. 그래서 슬롯만으로는 차별이 안 돼요. 우리 게임의 중심은 **"무엇과 무엇을 합치면 어떤 신화룡이 나오나"를 추리하고 발견하는 재미**예요. 슬롯은 알을 얻는 입구일 뿐이에요.

## 2. 목표 · 비목표 · 실패 기준

**목표**
- 처음 켠 사람이 10초 안에 첫 스핀을 돌린다.
- 한 판은 20~30분 안에 끝난다.
- 본편(3원소)만으로 완결된 게임이다.
- 같은 코드로 스팀(PC·스팀 덱)에 먼저 내고, 안드로이드·iOS로 이어서 낸다.
- 시즌마다 새 원소와 새 드래곤을 데이터 추가만으로 넣을 수 있다.

**비목표 (본편 출시 때 하지 않음)**
- 실시간 대전, 고스트 아레나, 서버 랭킹 검증, 계정 시스템
- 4원소 이상, 원소당 7종 이상
- 3개 이상 언어(한국어·영어만)
- 콘솔 이식

**실패 기준 (돌아가도 실패로 보는 것)**
- 슬롯 운에 따라 판이 그냥 끝나 버려서, 플레이어가 "내가 한 게 없다"고 느낀다.
- 조합 결과가 거의 흡수로만 나와서 발견하는 재미가 없다.
- 돈을 내고 랜덤을 돌리는 구조이거나, 도박처럼 보인다.
- 예전 계획처럼 기능을 늘리다가 출시를 못 한다.

## 4. 만드는 방법 (Approaches)

| 안 | 내용 | 판단 |
|---|---|---|
| **A. 웹 기술 (선택)** | TypeScript + Phaser + Vite. 스팀은 Electron, 모바일은 Capacitor로 포장 | **선택.** AI가 매번 브라우저에서 직접 플레이하고 확인할 수 있어서 반복이 가장 빨라요. 코드 하나로 세 플랫폼에 다 내요. 뱀파이어 서바이버도 처음엔 Phaser로 만들었어요. |
| B. 웹 검증 후 유니티 6 | 2~3주 웹 프로토타입 뒤 유니티로 다시 작성 | 모바일·콘솔에는 유리하지만, 다시 짜는 비용이 들고 에디터 작업을 AI가 직접 확인하지 못해요. |
| C. Godot 4 | 무료 엔진, 텍스트 씬 파일 | 브로테이토가 선례예요. 다만 AI 참고 예제가 적고 화면 확인이 번거로워요. |

사용자가 정한 조건은 "스팀 목표 + 안드로이드·애플 앱스토어도 고려"예요. 엔진은 그 조건에 맞춰 지휘자(Claude)가 A로 정했어요. 규칙 코드(core)는 화면 코드와 완전히 분리해요. 그래서 A가 막히면 B나 C로 규칙을 옮길 수 있어요.

## 6. 게임 설계

### 6.1 한 웨이브의 흐름
```
[석판 돌리기] → [가운데 줄 3개 중 알 1개 고르기 + 줄 맞춤 보너스]
   → [둥지에서 합치기·배치] → [자동 전투] → [보상(마력)] → 다음 웨이브
```

### 6.1.1 판의 승패 (사용자 결정)
- 생명 5개로 시작해요. 일반 웨이브에서 지면 생명 1개, 심판 보스에게 지면 생명 2개를 잃어요. 진 웨이브도 다음 웨이브로 넘어가요.
- 생명이 0이 되면 판이 끝나요. 20웨이브 보스를 잡으면 승리예요.
- 주간 시드 점수의 재료: 클리어 웨이브, 남은 생명, 사용한 스핀 수. 공식은 시뮬레이션으로 정해요.

### 6.1.2 알과 보관 (지휘자 판단)
- 가운데 줄의 알 3개는 스핀 순간 종까지 정해져서 카드에 보여요(예: "화염 와이번 알"). 플레이어가 알고 고르기 때문에 A+A, A+B, B+B는 선택의 문제가 돼요.
- 고른 알은 바로 부화해 대기칸(4칸)에 들어가요. 대기칸과 둥지 사이에서 끌어다 놓아 합칠 수 있어요.
- 대기칸이 차면 합치거나, 마력을 받고 놓아줘요. 전투에는 둥지 칸만 나가요.

### 6.2 룬 석판(슬롯) 규칙
- 3×3 칸, 심볼 5종: 화염 알, 빙결 알, 번개 알, 황금 알(마력), 여의주(아무 원소나 대신함). 처음 가중치는 v3.0 값(26/26/26/13/9)으로 시작하고 시뮬레이션으로 고쳐요.
- **가운데 가로줄**의 3칸이 그대로 이번 웨이브의 "알 3택 1" 후보예요. 그래서 꽝이 없어요.
- 줄 맞춤: 가로 3, 세로 3, 대각선 2, 모두 8줄이에요. 같은 원소 3개가 한 줄이면 보너스 알 1개와 마력, 2줄 이상이면 2티어 알이에요.
- **밀기**: 웨이브당 1회, 세로 줄 하나를 위나 아래로 1칸 밀 수 있어요.
- **천장**: 줄 맞춤 없이 연속 N번(시작값 4) 돌면 다음 스핀은 줄 하나가 반드시 맞아요.
- 웨이브마다 첫 스핀은 무료이고, 다시 돌리려면 마력이 들어요(갈수록 비싸져요).
- 배속 1x/2x/4x, 돌리는 연출 건너뛰기는 처음부터 넣어요.
- 금지: 동전·칩·베팅액 연출, "JACKPOT" 같은 카지노 문구, 돈으로 스핀 구매.

### 6.3 조합 규칙
- **기본종 + 기본종 (같은 원소)**: 기본종이 A(드레이크), B(와이번) 둘이라 조합은 A+A, A+B, B+B 세 가지예요. 이 셋이 각각 2티어 3종이 돼요.
- **2티어 + 2티어 (같은 원소)**: 정해진 한 쌍이 1티어(최상위)가 돼요. 나머지 쌍은 흡수돼요. 도감에 신화 힌트를 보여 줘요.
- **2티어 + 2티어 (다른 원소)**: 원소 짝마다 이중원소룡 1종이 나와요(화염+빙결, 화염+번개, 빙결+번개).
- **숨은 1종**: 특정 조건(초안: 이중원소룡 + 남은 원소의 1티어)으로만 나와요. 도감에서는 "???"로만 보여요.
- **레시피가 없으면 흡수**: 왼쪽(주인)은 종을 그대로 유지하고, 오른쪽(재료)은 사라져요. 주인은 재료의 계승 특성 1개(최대 2칸)와 능력치 상승을 받아요.
- 모든 레시피는 순서와 상관없이 같은 결과예요.
- **레시피는 모든 플레이어에게 고정이에요(사용자 결정).** 신화 힌트가 말이 되고, 커뮤니티에서 정보를 나눌 수 있어요. 도감 완성은 처음 5~10시간의 목표예요. 그 뒤의 반복은 빌드, 재앙 단계, 주간 시드가 맡아요. **시즌마다 숨은 종을 더해** 발견하는 재미를 다시 불러와요.

### 6.4 출시 로스터 초안 (22종)
| 원소 | 기본종 A / B | 2티어 (A+A / A+B / B+B) | 1티어 |
|---|---|---|---|
| 화염 | 마그마 드레이크 / 화염 와이번 | 베오울프 화룡 / 파프니르 / 시우코아틀 | 촉룡 |
| 빙결 | 빙하 드레이크 / 서리 와이번 | 팔라이유크 / 북해흑룡 오순 / 아지 라오이디타 | 쿠라오카미 |
| 번개 | 뇌운 드레이크 / 폭풍 와이번 | 베이시르 / 동해청룡 오광 / 케찰코아틀 | 응룡 |

- 이중원소: 열충격룡(화염+빙결), 선더버드(화염+번개), 교룡(빙결+번개)
- 숨은 1종: 원초룡 티아마트(오색 다두 묘사는 금지)
- 역할 경향: A 계열은 전열 탱커, B 계열은 후열 딜러, A+B는 지원형
- 이름과 설정은 제미나이로 신화 사실을 검수한 뒤 확정해요.

### 6.5 전투
- 둥지 6칸(전열 3, 후열 3). 자동 전투, 고정 틱(초당 20틱).
- 상성: 강한 쪽 ×1.35, 약한 쪽 ×0.75 (시작값).
- 적 전투력: `P(w) = 100 × 1.18^(w-1)`, 심판 웨이브 배율 5W ×1.65, 10W ×1.80, 15W ×1.95, 20W ×2.30 (시작값).
- 심판 보스 4종의 기믹은 예전 문서의 4대 재앙을 바탕으로 하되, 3원소에 맞게 다시 써요.
- 타격감: 맞은 순간 멈춤(히트스톱), 흰색 번쩍임, 화면 흔들림, 튀어 오르는 데미지 숫자, 드래곤 돌진 트윈. 그래픽 대신 이걸로 재미를 낸다.

### 6.6 반복해서 하게 만드는 장치
- **도감**: 발견한 종, 실루엣과 힌트, 완성률을 보여 줘요. "다음 시즌" 잠금 탭이 있어요.
- **최초 발견 연출**: 처음 만든 종은 화면 전체 연출로 보여 줘요. 스트리머 클립이 나오는 지점이에요.
- **재앙 단계 1~5**: 깨면 다음 단계가 열려요. 단계가 오를수록 규칙이 쌓여요.
- **주간 시드**: 전 세계가 같은 시드로 해요. 스팀 리더보드에 올려요.
- **해금**: 도감 완성률에 따라 시작 보너스 선택지가 늘어나요.
- **결과 카드**: 판이 끝나면 내 둥지 6마리를 이미지 한 장으로 저장할 수 있어요. 공유용이에요.
- **스팀 도전과제**: 1티어 첫 발견, 재앙 5단계 클리어 등.

### 6.7 초반 기대를 끄는 요소 (데모부터 넣음)

## 7. 기술 설계

```
dragon-game/
├─ packages/core/      # 규칙: 슬롯, 조합, 전투, 웨이브, 난수. 화면(Phaser·DOM) 참조 금지
├─ packages/view/      # Phaser 화면: core의 이벤트를 받아 연출만
├─ data/*.json         # 드래곤, 레시피, 석판 가중치, 웨이브, 보스, 재앙
├─ tools/sim/          # Node 명령줄 밸런스 시뮬레이터(봇 수천~수만 판)
├─ tools/lint-data/    # JSON 검사: 빠진 ID, 중복 레시피, 고아 종
├─ apps/web/           # Vite 개발 서버 (브라우저 플레이)
├─ apps/desktop/       # Electron + 스팀 연동 (뒤 단계)
└─ apps/mobile/        # Capacitor (뒤 단계)
```

**불변 규칙 (CLAUDE.md, AGENTS.md에 그대로 넣음)**
1. `packages/core`는 Phaser, DOM, `Math.random`, `Date.now`를 쓰지 않는다. 난수는 주입한 시드 난수만 쓴다.
2. 전투는 고정 틱으로 계산하고, 화면 프레임 속도와 상관없이 같은 결과가 나온다.
3. core 안에서는 `Math.sin` 같은 삼각함수와 실수 누적에 기대지 않는다(정수나 고정소수점 위주). 플랫폼이 달라도 같은 결과가 나오게 하기 위해서다.
4. 수치는 코드에 박지 않고 `data/*.json`에서 읽는다.
5. core는 이벤트 목록(누가 누구를 쳤나 등)을 내보내고, view는 그걸 받아 그리기만 한다.

**입력·플랫폼 (지휘자 판단)**
- 입력은 처음부터 "선택 커서" 방식으로 추상화해요. 터치, 마우스, 게임패드가 같은 동작(고르기, 끌어 놓기, 확인)을 내요.
- 스팀 덱은 출시 때 "플레이 가능"이 목표예요. "인증"은 3단계에서 패드 조작을 다듬어 신청해요.
- 모바일도 유료 앱으로 팔아요. 광고와 유료 랜덤은 넣지 않고, 원소팩은 1회 결제로 팔아요. 기기 간 저장 연동은 출시 후에 붙여요.

**테스트**: core는 Vitest로 단위 테스트, 같은 시드는 같은 결과 테스트, 데이터 검사. 화면은 브라우저 플레이 확인(필요하면 Playwright).
**저장**: 웹은 localStorage/IndexedDB, 데스크톱은 파일, 스팀 클라우드는 뒤 단계에 붙여요.

### 8.2 Godot 전환 (사용자 결정 2026-11-23)

- **엔진·언어**: Godot 4.7.2, GDScript. 설치 위치 `C:\claude\tools\godot`. 스팀(PC)·안드로이드·iOS·웹 내보내기를 한 엔진으로.
- **프로젝트 위치**: 저장소 맨 위에 `project.godot`. `data/*.json`과 `assets/dragons/*.png`를 웹판과 함께 써요. Godot가 읽을 필요 없는 폴더(`node_modules`, `packages`, `apps`, `tools`, `docs`, `release*`, `dist*`, `art`)에는 `.gdignore`.
- **규칙 이식 원칙**: TypeScript 규칙(`packages/core`)을 GDScript(`godot/core/`)로 그대로 옮겨요. 정수 계산과 시드 난수는 비트 단위로 같아야 해요.
- **일치 검사**: TypeScript판이 "같은 시드·같은 명령 → 이벤트와 상태" 기준 자료(`godot/tests/fixtures/*.json`)를 만들고, GDScript판이 같은 결과를 내는지 Godot를 화면 없이 돌려 확인해요. 이 검사가 통과해야 Godot판을 믿어요.
- **웹판의 역할**: Godot판이 같은 기능에 도달할 때까지 웹판(TypeScript+Phaser)은 기준이자 시험판으로 남겨요. 밸런스 시뮬레이터도 당분간 TypeScript판을 써요.
- **순서**: G0 뼈대·테스트 실행기·일치 검사 자료 → G1 규칙 이식(코덱스) → G2 화면(코덱스 초안, Claude 다듬기) → G3 Steam(Windows) 내보내기 → G4 모바일.

**이미 내고 있는 구독**: 월 420달러(약 57만 원) × 6~7개월 ≈ 340만~400만 원. 병렬 개발에서는 두 구독을 모두 바쁘게 쓰니, 지금 요금제를 유지해요.

**손익분기 감각**: 9.99달러에 팔면 스팀 수수료, 세금, 지역가격, 환불을 빼고 한 장에 대략 4.5~5달러가 남아요. 새로 나가는 돈만 회수하려면 약 300~400장, 구독비까지 회수하려면 약 1,100~1,300장이에요. 추정치예요.

## 12. 위험과 대응

| 위험 | 대응 |
|---|---|
| Slotbound와 비슷하다는 평가 | 조합 발견과 신화 도감을 앞세우고, 용어·화면 배치는 다르게 해요 |
| 사행성 판정 | 6.2의 금지 목록을 지키고, 출시 전 등급분류 기준을 확인해요 |
| 범위가 커짐 | 비목표 목록에 없는 기능은 시즌으로 미뤄요 |
| 부업 번아웃 | 단계마다 통과 기준으로 끊고, 0단계에서 재미를 먼저 확인해요 |
| 웹 성능·모바일 | 1단계부터 스팀 덱과 중급 안드로이드에서 시험해요 |
| 결정론 깨짐 | 7장 규칙 3번, 같은 시드는 같은 결과인지 자동 테스트 |
| 신화 이름·묘사 | 제미나이 검수, 유명 게임의 묘사를 피함 |

| AI 그림 화풍 불일치 | 고정 프롬프트 틀과 후처리 규칙을 1단계 초에 확정해요 |
| 병렬 작업 충돌·품질 저하 | 폴더 소유권과 계약 먼저 원칙을 지키고, 코덱스 결과는 테스트와 diff 검토를 거친 뒤에만 합쳐요 |
| 두 구독의 사용량 한도 | 큰 작업을 몰아서 맡기지 않고, 한도에 가까워지면 그 주에는 검토·플레이 확인 위주로 해요 |

## 13. 만드는 사람에게 맡기는 것
- 모든 수치(능력치, 가중치, 비용, 배율)의 최종값. 시작값에서 시뮬레이션으로 조정해요.
- 계승 특성, 스킬, 보스 기믹의 구체적인 내용
- 화면 세부 배치(가로 모드, 터치 기준이라는 원칙만 지키면 돼요)
- Phaser 버전, 상태관리 방식, 폴더 세부 구조
- 아트 스타일 세부. 원칙은 굵은 외곽선의 단순한 2D이고 화풍을 하나로 통일하는 거예요.
