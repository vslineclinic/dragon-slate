# 1단계 핵심 완성 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 한 판을 20웨이브로 늘리고, 심판 보스 4종에 실제 기믹을 넣고, 도감 화면과 시작·결과 화면을 붙여서 "핵심이 다 있는" 게임으로 만든다.

**Architecture:** 보스 기믹은 core 전투에 데이터로 주입하는 규칙(`BossRules`)으로 넣고, 이벤트(`hazard`)로 화면에 알린다. 보스 정의·도감 문구는 `data/bosses.json`, `data/codex.json`. 화면은 Phaser 오버레이(도감)와 새 장면(시작)으로 붙인다. 코덱스는 밸런스 지표(X3)와 도감 문구 초안(X4)을 동시에 맡는다.

**Tech Stack:** 0단계와 같음 (Node 26, TypeScript 7, Vite 8, Vitest 5, Phaser 4.2)

**Spec:** `docs/superpowers/specs/2026-11-23-wyrmslot-design.md` (6.5 전투, 6.6 반복 장치, 9장 1단계)

## Global Constraints
- 0단계 계획서(`2026-11-23-phase0-prototype.md`)의 Global Constraints 전부 그대로.
- 판 길이: `maxWave` 20, 보스 웨이브 5·10·15·20, 둥지는 5·10·15웨이브 뒤 1칸씩(최대 6).
- 보스 기믹 수치는 전부 `data/bosses.json`에서 읽는다. 기믹 피해는 "최대 체력의 %"이고 정수 내림, 최소 1.
- 보스 예보는 1·6·11·16웨이브 시작 때 다음 보스의 이름·기믹·대응 힌트를 보여 준다.
- 0단계 통과 기준(5명 시험)은 사용자가 직접 플레이해 본 것으로 대신하고 1단계로 넘어간다(사용자 결정 2026-11-23).

## Review Focus
1. **기믹 피해로 아군이 전부 죽는 경우**: 적 승리로 끝나고 death 이벤트가 한 번씩만 나온다 → B1 테스트 `hazard kills emit single death and end battle`
2. **흡혈 중 회복 감소 기믹**: 회복량이 정확히 줄고 음수가 되지 않는다 → B1 테스트 `heal cut reduces lifesteal`
3. **도감에서 숨은 종(티아마트) 정보 노출**: 발견 전에는 이름·레시피 대신 "???"와 힌트만 → B4 확인 단계
4. **결과 화면에서 새 판 시작 후 이전 판 상태 잔존**: 둥지·마력·보상 상태가 완전히 초기화 → B5 확인 단계(새 판 직후 상태 확인)
5. **4x 배속에서 기믹 연출 과다**: 숫자 생략, 판정은 동일 → B3 확인 단계

### Task B1: 보스 규칙을 전투에 (Claude)
**Files:** Modify `packages/core/src/battle.ts`, `packages/core/src/contracts/events.ts`, `packages/core/src/contracts/types.ts` · Test `packages/core/test/boss.test.ts`

**Interfaces (Produces):**
```ts
// types.ts
export interface BossRules {
  healCutPct?: number;                                        // 흡혈 회복 감소(%)
  healCutFromTick?: number;
  burn?: { everyTicks: number; pct: number };                 // 체력이 가장 낮은 아군 1기에 최대체력 pct% 피해
  rowBlast?: { everyTicks: number; pct: number };             // 전열(0~2)·후열(3~5)을 번갈아 그 줄 전원에 pct%
  allySlowPct?: number;                                       // 아군 쿨타임 +pct%
  enrage?: { atTick: number; atkPct: number };                // atTick부터 적 공격력 atkPct%
  pulse?: { everyTicks: number; pct: number };                // 아군 전원 pct%
}
// events.ts BattleEvent에 추가
| { tick: number; kind: 'hazard'; name: 'burn' | 'rowBlast' | 'pulse'; idx: number; dmg: number }
| { tick: number; kind: 'enrage' }
// battle.ts
export function simulateBattle(cfg: BattleConfig, allies: (Unit | null)[], enemies: (Unit | null)[], rules?: BossRules): BattleResult
```
- 처리 순서: 틱마다 (1) 기믹(`burn`→`rowBlast`→`pulse`, 해당 틱이 everyTicks의 배수일 때) (2) 아군 공격 (3) 적 공격. 기믹으로 죽으면 death 이벤트. `rowBlast`는 첫 발동이 전열, 다음 후열, 번갈아.
- `allySlowPct`: 아군 쿨타임 = floor(cd × (100+pct)/100). `enrage`: atTick 이상에서 적 피해 = floor(dmg × atkPct/100), enrage 이벤트 1회.
- [ ] **Step 1:** 테스트: `burn hits lowest hp ally every N ticks`, `rowBlast alternates front and back rows`, `ally slow lengthens cooldown`, `enrage multiplies enemy damage after tick`, `heal cut reduces lifesteal`, `hazard kills emit single death and end battle`, `no rules means unchanged result`(기존 JSON 비교).
- [ ] **Step 2~4:** FAIL → 구현 → PASS, `npm test` 전체.
- [ ] **Step 5:** 커밋 `feat(core): boss rules (burn, row blast, slow, enrage, pulse, heal cut)`
